# Healthcare Analytics Portfolio Release Plan

**Owner:** Sieanna Smith  
**Plan established:** October 18, 2026  
**Purpose:** Publish polished case studies in a clear sequence while preserving truthful research, completion, and GitHub publication dates.

## Date policy

- **Analysis started:** Actual date work began, verified from notebooks, files, notes, or source history.
- **Initial analysis completed:** Actual date the defined analysis first produced validated outputs.
- **Case study finalized:** Actual date methods, findings, limitations, figures, and reproducibility documentation pass review.
- **GitHub publication:** Actual date the repository or release becomes publicly accessible.
- **Later updates:** Keep their own real commit/release dates.
- Do **not** backdate Git commits, invent completion dates, or label a working study finalized.
- Use **month/year** on resumes when appropriate; retain more precise dates in project records when supported.

## Publication gate checklist (each project)

- [ ] Verify dataset origin, license/access, and data-handling restrictions.
- [ ] Validate totals, units, denominators, percentages, and displayed precision.
- [ ] Run and document reproducibility checks (and disclose any unverified steps).
- [ ] Review statistical methods, interpretation, uncertainty, and limitations.
- [ ] Inspect figure labels, title alignment, tables, captions, and accessibility.
- [ ] Remove credentials, protected data, local paths, and unnecessary artifacts.
- [ ] Record the real analysis period, initial completion, case-study finalization, and publication dates.
- [ ] Publish a clear README and appropriately scoped release only after passing checks.
- [ ] Align resume and LinkedIn language with verifiable project status.

## Job application presentation

Use **Selected Healthcare Analytics Projects (2026-present)** as a collective heading when useful. Describe each project by its *actual status and evidence*. The existence of a public GitHub repository is not proof that its analysis is finalized.

This plan is an operational schedule, not a retrospective account of completed work.
